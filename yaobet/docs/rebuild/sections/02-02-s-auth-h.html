Transitions. signIn(as = "tiered") sets the state. signOut() sets guest. cycleDevState() cycles guest → level-0 → tiered → guest (dev toggle only). The state is React state only, so a page reload resets it to "tiered". Modal state: {open:false, mode:"login", resumeIntent:{action:"none"}}. openAuthModal({mode = "login", resumeIntent = {action:"none"}}) replaces all three fields. closeAuthModal() sets open:false and keeps mode and intent. consumeResumeIntent() returns the intent and resets it to none. AuthModal

Purpose. The single login / register / forgot-password surface. Below 640px it is a bottom sheet holding only the form. From 640px it is a 720px centred dialog with a 280px brand panel on the left.

Validation. Native HTML required handles the required fields (browser bubble, no custom message). There is one client rule: in register, if Mật khẩu ≠ Xác nhận mật khẩu, the confirm field shows "Mật khẩu xác nhận không khớp" (Passwords do not match) and submit stops. Editing the confirm field clears that error. No length, format or phone checks exist.

Already submittingIgnored (single flight).
forgotsubmitting=true. After 600ms: sent=true, submitting=false. Shows the success text "Đã gửi hướng dẫn đặt lại mật khẩu. Vui lòng kiểm tra email hoặc tin nhắn." plus "Quay lại đăng nhập".

register (no deposit intent)signIn("level-0"), close immediately.
loginsignIn("tiered"), close immediately. Any credentials are accepted.
Cancel (✕, Esc, scrim, swipe)closeAuthModal; focus returns to the trigger; the intent is kept.
Mode switchopenAuthModal with the new mode and the same intent. Because key={mode}, the body remounts and every field resets.

/* AuthField — TextField analog for the auth modal.
 *
 * FLAT / DARK-LUXURY input contract (30-PM-DESIGN-SYSTEM, as CORRECTED 2026-08-17):
 *   resting → filled --surface-3 PLUS a 1px --border hairline;
 *   focus   → a 2px SOLID accent border. Never a glow/shadow ring (the flat
 *             system bans depth, and --glow-gold/--halo/--lift are `none`).
 *
 * The original ruling said "resting = filled surface, NO border". That was a
 * literal translation of the light-mode system ("Gray 100 background. No
 * border."), and it does not survive the palette swap: --surface-3 #212121 on
 * the modal's --surface #141414 is 1.14:1, so a border-less field has no
 * boundary at all and fails WCAG 1.4.11 (3:1 for UI component boundaries). The
 * flat system removes shadow, gradient AND border simultaneously; in a light
 * palette white-on-gray-100 survives that, at near-black on near-black nothing
 * does. The hairline is therefore load-bearing here exactly as it is on cards.
 * PM reversed the rule; this is the corrected build. DO NOT "fix" it back.
 *
 * Focus stays a WEIGHT change in the SAME hue (1px 55%-alpha gold → 2px solid
 * gold), never a second colour. Padding compensates the extra border pixel so
 * the box geometry is byte-identical in both states — no reflow on focus.
 *
 * The blue --focus-ring stays reserved for :focus-visible on the icon button;
 * it is NEVER a resting/selected colour. */

   * identical at rest (1 border + 1 pad) and at focus (2 border + 0 pad). */

     sweep areas (one used --brand-accent here, one used --focus-ring).
     Focus is ONE affordance and gets ONE colour: a user learns "blue = where I
     am" once, or not at all. Two reinforcing reasons for blue over gold:
       · --focus-ring is the PINNED, AA-guaranteed indicator (8.21:1 vs canvas),
         locked identical across brands. Gold is not.
       · On this product gold is REWARD chrome. Focus is not a reward, and the
         trust surfaces (contribution/restricted) already forbid brand accent
         for exactly that reason.
     The design system's "border-2 solid Primary" was written for a light
     palette where Primary WAS the focus blue and the two coincided. In dark
     gold they diverge, and the accessibility token wins. */
  border-color: var(--focus-ring);
