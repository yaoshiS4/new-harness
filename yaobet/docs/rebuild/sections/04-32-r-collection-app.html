6. States

  • Tile: not held → CardArt ghost (grayscale .85, brightness .62, opacity .72), no badge; held 1 → colour, no badge; held ≥2 → "×N".
  • Rail complete → "Sẵn sàng đổi" + enabled "Đổi thưởng"; incomplete → button disabled (no explanation). After ≥1 exchange: "Đã đổi N lần".
  • Rail pulse after an open: each set the drawn card belongs to gets .pulse, staggered i × 80ms; all cleared at 900ms.
  • Busy (draw or exchange in flight): all "Đổi thưởng" disabled; stage CTA disabled.
  • Draw rejected: toast with the reason (tap to dismiss).
  • Focus-visible: 2px #6ea8ff offset 2px on .btn/.primary/.entryPill/.sheetClose/.sheetLink.

7. Motion

rail/entryPill/sheetClose/btn transitions 200ms ease-standard (transform, background-color, border-color, color). Reduced motion: transitions and hover transforms removed.

9. Data

state.get → CollectionState; DEMO_SETS/cardsInSet for rails; heldById map (count, firstAcquiredAt); vested entitlements count.

10. Behaviour & a11y

  • openOne: if busy or no vested → no-op. Takes vested[0], draw with key "draw-{id}", sets last, refreshes, pulses rails.
  • proposeClaim(setId): computes exchangeImpact, opens RewardCeremony in confirm phase (nothing spent). confirmClaim: impact → null (ceremony phase), credit, then grant or error; refresh.
  • Rail anchors (id = set.id) are the targets of CardDetail's "Có trong:" links.
Rail order is "frozen at the first successful load" per comment, but every demo action remounts CollectionApp (key = nonce), so the order is recomputed after each "+1 lượt mở" / "Hoàn thành 1 bộ" / "Đặt lại". The toast comment says it carries the payout transaction id; it is only used for draw rejections. The comment above railFacts mentions "five fields" — there are two. CardArt instances repeat the same SVG ids (c-{cardId}-bg …) when a card appears on several rails.
