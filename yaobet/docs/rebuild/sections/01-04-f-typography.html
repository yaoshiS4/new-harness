Both are imported from next/font/google, which self-hosts them at build time. The .variable classes go on <html className>, and Next defines --font-be-vietnam / --font-montserrat there with hashed family names. The chain is --font-be-vietnam → --font-body / --font-num (raw ramp) → --brand-font-body / --brand-font-num (what components read). Montserrat follows --font-montserrat → --font-head → --brand-font-head and --brand-font-display. There are no @font-face rules and no @import of fonts anywhere. public/assets has no fonts/ folder (the README calls it "future").

Weight coverage gaps (fact from the loader config). Montserrat loads only 700 and 800. Be Vietnam Pro loads only 400/600/700. Heading rules use --weight-bold (700, available). Any font-weight: 600 on a Montserrat element would be synthesised or snapped to 700 by the browser. .u-label uses 800, which is loaded for Montserrat. Any element using Be Vietnam Pro at 800 would fall back to the nearest available weight, 700 (inference: browser weight matching).

reset.css sets html { font-size: 14px }. Every token is in absolute px, so this affects only rem/em/ch-based values. In src/ui those are Button .icon 1.25em, .spinner 1.1em, Pill .icon 1.1em, Icon size default 1em, Skeleton height default 1em, and the 40ch/60ch/2ch measures.

Document-level type cascade (exact order)

  1. typography.css body: font-family: var(--brand-font-body); font-size: var(--t-body) (16px); line-height: var(--lh-body) (1.5); font-weight: var(--weight-reg) (400); color: var(--text-hi) (#f2f0e4).
  2. typography.css h1–h6: font-family: var(--brand-font-head) (Montserrat); letter-spacing: -0.02em.
  3. globals.css h1–h6 (loads after): font-weight: var(--weight-bold) (700); line-height: var(--lh-tight) (1.3). Heading font-size is not set globally, so browser defaults apply unless a component sets one.
  4. globals.css body repeats font-family, font-size, line-height and color, and adds background: var(--canvas), min-height: 100%, overflow-x: hidden.
  5. globals.css small: font-size: var(--t-sm) (14px); color: var(--text-mid) (#888888).
globals.css says "Headings inherit the body face", but typography.css sets headings to --brand-font-head (Montserrat). The comment is stale; the code wins. Browser-default heading sizes apply (e.g. h1 = 2em of the parent's size) wherever a component does not set font-size.

Numeric / tabular rules

  • Every money, odds, count and countdown primitive sets font-family: var(--brand-font-num); font-variant-numeric: tabular-nums; font-feature-settings: "tnum" 1. This covers MoneyValue .money, Odometer .odometer and Countdown .countdown. MoneyValue and Odometer also set white-space: nowrap; Countdown does not.
  • Number formatting lives only in src/lib/format.ts (see f-lib-format). VND uses . thousands grouping and a trailing " ₫". Odds use 2 decimals with a . decimal point. Percent uses a , decimal only when decimals are requested.
Verbatim src/styles/typography.css
/* ============================================================================
 * Yaobet — typography layer (SPEC-04 styles/typography.css)
 * ----------------------------------------------------------------------------
 * TWO faces, both Vietnamese-complete (Flat / Dark-Luxury, PM ruling A4):
 *
 *   Be Vietnam Pro  → body / numerals   (--brand-font-body / --brand-font-num)
 *   Montserrat      → display, headings, uppercase labels (--brand-font-head)
 *
 * Outfit is REJECTED and must not be reintroduced. Measured against the Google
 * Fonts API: Outfit serves `latin` + `latin-ext` only, and latin-ext covers
 * U+1E00–1E9F plus U+1EF2–1EFF while SKIPPING U+1EA0–1EF1 — precisely the
 * block holding the toned Vietnamese vowels. `BỘ SƯU TẬP` (Ộ = U+1ED8) and
 * `Đổi thưởng` (ổ = U+1ED5, ở = U+1EDF) both fall out of the face mid-word.
 * Montserrat and Be Vietnam Pro BOTH serve the `vietnamese` subset
 * (U+1EA0–1EF9), so every string in this product renders in one typeface.
 *
 * LOADING: next/font/google in app/layout.tsx, injected as --font-be-vietnam
 * and --font-montserrat on <html>. tokens.css wraps them in the raw-ramp
 * --font-body / --font-num / --font-head, and components read only the
 * --brand-font-* aliases (lint A2). No @font-face and no @import here.
 * ==========================================================================*/

/* Base type ramp. Components read --t-* / --weight-* tokens; these are the
 * document-level defaults so unstyled VN copy is already on the AA ladder. */
body {
  font-family: var(--brand-font-body);
  font-size: var(--t-body);
  line-height: var(--lh-body);
  font-weight: var(--weight-reg);
  color: var(--text-hi);
}

/* ---- Display / headings -------------------------------------------------
 * Montserrat, tightened to -0.02em per the design system. Weight and
 * line-height are set by globals.css (which loads after this sheet), so this
 * rule deliberately declares family + tracking ONLY — no cascade fight.
 * /vip headings opt out by class (.vipSectionHeading etc. carry
 * --brand-font-display at class specificity, which wins over these element
 * selectors), so the Cinzel luxury layer is untouched. */
h1,
h2,
h3,
h4,
h5,
h6 {
  font-family: var(--brand-font-head);
  letter-spacing: -0.02em;
}

/* ---- Uppercase labels ---------------------------------------------------
 * The system's "tracking-wider" treatment: display face, heaviest weight,
 * OPEN tracking (uppercase VN needs the extra sidebearing — stacked tone +
 * vowel marks collide at negative tracking). A global opt-in hook, matching
 * the [data-numeric] convention below: CSS Modules hash their own class names,
 * so a module cannot reach this rule by accident. Apply with
 * className="u-label" or data-label="upper". */
.u-label,
[data-label="upper"] {
  font-family: var(--brand-font-head);
  font-weight: 800;
  text-transform: uppercase;
  letter-spacing: 0.06em;
  line-height: var(--lh-tight);
}

/* Tabular numerals so money/odds don't reflow on tick (SPEC-02 §4 / A8). */
.money,
[data-numeric] {
  font-family: var(--brand-font-num);
  font-variant-numeric: tabular-nums;
}
