Runtime and mock auth

Session state is mock and in memory: MockAuthProvider in src/lib/auth/session.tsx holds one of three states, guest (signed out), level-0 (registered, no tier) and tiered (member with a VIP tier). The provider's own default is guest, but src/app/providers.tsx mounts it as <MockAuthProvider initialState="tiered">, so every page load starts signed in as the tiered member. Nothing is persisted, so a full reload always returns to tiered. The rebuild must keep this behaviour, because several screens render different content per state.

  • Register in the auth modal signs the user in as level-0; log in signs them in as tiered.
  • In development only, the home page shows a DEV floating button (aria-label Mở bảng chuyển trạng thái đăng nhập (dev)). It opens a panel whose cycle button steps guest → level-0 → tiered → guest, labelled Khách, Cấp 0, Hội viên. In production builds it renders nothing.
  • To see signed-out or level-0 screens, cycle the state on the home page, then navigate client-side (links or router push). A typed URL reloads the page and puts you back in tiered.
