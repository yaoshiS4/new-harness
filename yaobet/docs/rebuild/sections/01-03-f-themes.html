themes.css & brands.css — the two orthogonal axes

<html> carries two attributes. data-theme is the canvas/surface axis (reserved, a no-op at v1). data-brand is the accent/CTA/font/logo axis. Both are set statically in src/app/layout.tsx as <html lang="vi" data-brand="yaobet" data-theme="obsidian" className={`${beVietnamPro.variable} ${montserrat.variable}`}>. No code ever changes them at runtime: no theme or brand switcher exists, and no other data-brand/data-theme attribute exists in src (verified with rg).

[data-theme="obsidian"] — themes.css

This is an empty rule (comment only). It overrides nothing. The obsidian theme is the :root defaults.

[data-theme="obsidian"] {
  /* v1 Flat / Dark-Luxury == the :root defaults; no overrides needed yet. */
}
Verbatim src/styles/themes.css
/* ============================================================================
 * Yaobet — [data-theme] hook (SPEC-02 §0)
 * ----------------------------------------------------------------------------
 * Yaobet ships OLED-dark only at v1. [data-theme="obsidian"] is the reserved
 * hook for future light/alt themes. The default (no [data-theme]) IS obsidian;
 * this selector exists so the hook is wired and any future theme re-points
 * GROUP-A surface/text tokens here (NOT in brands.css). Brand and theme are
 * orthogonal axes: [data-brand] re-skins accent; [data-theme] re-skins canvas.
 *
 * Under the Flat / Dark-Luxury re-point, "obsidian" is now literally obsidian:
 * --canvas #0a0a0a, --surface #141414, --text-hi #f2f0e4 champagne, accent
 * #d4af37 gold. PM ruling A1 settled the light-vs-dark contradiction in the
 * source design system in favour of dark, so there is still exactly ONE theme
 * and this block stays a no-op. A future light theme would re-point the
 * GROUP-A canvas/surface/text ladder HERE — and would additionally have to
 * re-derive --border and --text-on-gold, which are tuned for a dark ground.
 * ==========================================================================*/

[data-theme="obsidian"] {
  /* v1 Flat / Dark-Luxury == the :root defaults; no overrides needed yet. */
}

[data-brand] blocks — brands.css

Two selectors exist. [data-brand="yaobet"] re-declares exactly the same aliases as :root, so it is an explicit default anchor and changes no pixel. [data-brand="emerald"] is a regression brand that nothing in the app activates. Both declare only the 12 --brand-* vars. Specificity: [data-brand] (0,1,0) on <html> beats :root (0,1,0) because brands.css is imported after tokens.css.

Brand-following tokens in the member-hub layer (--page-bloom, --header-card-grad, --progress-fill, --progress-fill-grad, --progress-tag-*) are declared on :root as color-mix(… var(--brand-accent) …). A custom property's var() is substituted on the element where it is declared, so these resolve against :root's --brand-accent (gold). <html> is the :root element and carries data-brand too, so under emerald they would follow emerald correctly. Moving data-brand onto a descendant (e.g. a <div data-brand>) would break this.
Verbatim src/styles/brands.css
/* ============================================================================
 * Yaobet — [data-brand] OVERRIDES (SPEC-02 §2.1)
 * ----------------------------------------------------------------------------
 * A [data-brand="x"] block re-points ONLY the GROUP-B --brand-* indirection
 * vars. It MUST NOT touch any GROUP-A LOCKED token (lint A1) and MUST NOT
 * redeclare a RAW-RAMP literal (--gold-*, --cta*, --font-body/-num,
 * --text-on-gold) — it overrides by re-pointing the --brand-* alias.
 *
 * --win / --loss / --error / --focus-ring are ABSENT from every block —
 * equal-salience + AA focus are LOCKED across all brands (lint A3). So are
 * canvas, contrast floor, spacing, radii, z-index and motion. This is the
 * falsifiable byte-identical property Wave 1.4 verifies / Wave 1.3 lints.
 * ==========================================================================*/

/* Default brand — Yaobet. The --brand-* aliases already resolve to the Yaobet
 * gold/CTA ramps on :root (tokens.css). This block is the explicit default
 * anchor so [data-brand="yaobet"] is a defined selector and the override
 * mechanism is symmetric with the alternate brand below. */
[data-brand="yaobet"] {
  --brand-accent:          var(--gold-500);
  --brand-accent-2:        var(--gold-600);
  --brand-accent-grad:     var(--gold-grad);
  --brand-accent-hairline: var(--gold-hairline);
  --brand-on-accent:       var(--text-on-gold);
  --brand-cta:             var(--cta);
  --brand-cta-grad:        var(--cta-grad);
  --brand-cta-accent:      var(--cta-accent);
  --brand-font-body:       var(--font-body);
  --brand-font-num:        var(--font-num);
  --brand-font-head:       var(--font-head);
  --brand-logo:            url("/assets/brand/logo.svg");
}

/* Regression brand — proves the override re-skins accent/CTA/logo/font while
 * canvas / win-loss / contrast / spacing / motion stay byte-identical. */

The /vip luxury palette

The VIP palette is defined in tokens.css on :root as the --vip-* tokens plus --brand-font-display (see f-tokens-vip). It is not a theme or brand selector. It applies through a page wrapper class .vipPalette in src/components/vip/VipProgram.module.css, rendered by VipProgram.tsx as <div className={styles.vipPalette}>. Track R owns the wrapper's own styles and every VIP component.
