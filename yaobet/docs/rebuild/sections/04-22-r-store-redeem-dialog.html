RedeemDialog

1. Purpose

Confirm-redeem modal showing the points it will cost (escalated when redeeming early), the balance before/after and the withdrawal condition, then a success receipt.

2. Source

Cost math

early = isCooldownRunning(product, nowMs); step = early ? currentStep + 1 : 1; pointCost = pointsAtStep(base, q, step, maxSteps); affordable = points ≥ pointCost; balanceAfter = points − pointCost; costTone = !affordable ? "alert" : early ? "caution" : "normal".

Dialog steps (state machine)

mount → phase "idle" (confirm)
  [Hủy | Esc | scrim] → onClose (unmount)
  [Xác nhận đổi / Đổi ngay] (affordable) → phase "submitting" (gold button loading)
        setTimeout 600ms → phase "success" (receipt)
  [Xong | close] → onClose
early countdown reaches 0 → onZero → nowMs = now → early false → cost drops to base, callout disappears, label back to "Xác nhận đổi"

10. Behaviour & a11y

Focus trap/Esc per Modal. Double-submit guarded (phase check).

After "success" the balance prop is not decremented — reopening any card still shows "Số dư hiện tại 3.250 điểm", and the receipt's remaining balance is never reflected in PointsHeader. The at_floor and unlimited_deep disclosures (vi.claim.atFloor, unlimitedDeep, earlyEscalated…) exist in i18n but are never rendered; an unlimited package escalates silently with no "no floor" warning. StoreTerms says "the exact points always show on the redeem button" but the early button reads only "Đổi ngay".
