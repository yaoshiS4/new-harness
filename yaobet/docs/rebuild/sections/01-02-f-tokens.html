Token contract — src/styles/tokens.css

The file holds one :root block with 163 custom properties, grouped below in file order with exact values. This is the only file in the app that may hold design literals. Every other stylesheet reads var(--…). The "resolved literal" column follows var() chains under the default brand ([data-brand="yaobet"] repeats the same aliases). var(--font-be-vietnam) and var(--font-montserrat) stay unresolved because next/font injects them on <html> at runtime (see f-typography).

  • GROUP A (locked base) is authored on :root only and is forbidden inside any [data-brand] block (lint A1).
  • GROUP B (i) raw ramp (--gold-*, --text-on-gold, --cta*, --font-body/-num) holds source literals that components must never var()-read (lint A2).
  • GROUP B (ii) --brand-* is the indirection layer that components read and brands re-point.
  • PINNED: --focus-ring, --win, --loss, --error must be standalone literals (lint A3).
  • There are no breakpoint tokens. CSS custom properties cannot be used in media queries, so every component hard-codes its media-query widths. The values seen in src/ui are max-width: 639px (Modal) plus hover/pointer feature queries.
  • There is no light theme and no prefers-color-scheme handling. globals.css sets color-scheme: dark on html.
Token hygiene findings:
  • 17 tokens are defined but never var()-read anywhere in src: --banner-mb --blue-soft --brand-logo --dur-header --field-rhythm --frame-min --glow-gold --halo --lift --progress-dot-glow --progress-tag-bg --progress-tag-border --shadow-2 --status-locked-bg --status-locked-text --vip-gold-grad --vip-negative.
  • The --shadow-2 comment says QuickActionRail reads var(--shadow-2, <fallback>). No such read exists any more, so the token is an orphan.
  • --brand-logo points to /assets/brand/logo.svg, but no CSS reads it. The Header and AuthModal hard-code <img src="/assets/logo.svg"> (a different file). So the emerald brand's logo override has no effect.
  • --progress-track's comment mentions "our OLED #1f222e", but the canvas is now #0a0a0a. That is a stale comment.
  • The --gold-grad and --cta-grad names say "grad", but both are solid colours (#d4af37, #1e3d59).
  • Under the emerald brand, --brand-accent-grad and --brand-cta-grad become real linear-gradient()s. Button reads --brand-cta-grad for .primary, so a primary button would carry a gradient under that brand. That breaks the "no button gradient" invariant (default brand unaffected).
  • --vip-text-* uses cool blue-greys (#e6ebf5, #8b96ad), while the app text ladder is warm champagne. The source comment says this seam is intentional.
  • The --brand-font-display comment still describes the removed Cinzel face. typography.css (line 39) still says "the Cinzel luxury layer is untouched" even though Cinzel is no longer loaded.

 *
 *   GROUP A  — LOCKED base. Never per-brand overridable. Authored on :root only;
 *              FORBIDDEN inside any [data-brand] block (lint A1).
 *   GROUP B  — Brand-overridable indirection. Splits into:
 *                (i)  RAW RAMP source literals (--gold-*, --cta*, --font-body/-num,
 *                     --text-on-gold) — default-brand source values; components must
 *                     NOT read these directly (lint A2).
 *                (ii) --brand-* INDIRECTION vars — the ONLY tokens a [data-brand]
 *                     block re-points and the ONLY brand-tinted vars components read.
 *
 * PINNED-to-neutral (§0.2): --focus-ring, --win, --loss, --error are standalone
 * LOCKED constants. They MUST NOT reference any --brand-* or RAW-RAMP token (lint A3).
 *
 * Components read brand/semantic/locked vars — NEVER raw ramp literals.
 * No component hardcodes a hex / px / duration; everything is var(--…).
 * ==========================================================================*/

   * 1.05:1 — surfaces CANNOT carry separation in this palette. The ladder
   * below is therefore intentionally tight (each step ~1.06–1.22:1) and the
   * gold hairline (--border / --gold-hairline) is the load-bearing edge.
   * Ladder is monotone-ascending: canvas < tile < surface < 2 < 3 < hover
   * < disabled, so "more elevated" is always "lighter" — no inversions. */
