# ADR-003 — Wine-Gold design system: alias migration

Status: proposed (sa, 2026-11-07; revised after critical-planner gate 1, which approved the alias architecture; the PM accepts it) · Date: 2026-11-07 · Author: sa · Amends: `docs/design/TOKENS.md` (the token contract) and `docs/rebuild/ADR-002.md` §1, but only where this file says so.
Binding inputs: `docs/design/DS-WINE-GOLD-REVIEW.md` §5 (owner decisions D-DS1..D-DS15 and PM rulings R1-R4; not re-opened here) · `docs/design/wine-gold/MAPPING.md` and `overlay.proposal.json` (the designer's mapping) · `docs/design/TOKENS.md` §4 (rules 4.1-4.3) and the tier rule (TOKENS.md:14).
Plan and gates: `.unlazy/yaobet-ds/PLAN.md`, `.unlazy/yaobet-ds/GATES.md`.

## 1. Context

Provenance: §1 describes the tree at 635a4dc, and every `src/` line citation in this ADR is read at that commit. `ds/inventory.md` (cited as `inventory:N` anywhere in this ADR) was the W1 explorer's scratch output and was not retained, so its counts cannot be re-checked. The 243-file count is re-checked on main by `npm run lint:rules` (RULES OK 243 files).

- Today the token source is `src/styles/tokens.css` (363 lines), plus `tw-theme.css`, `brands.css`, `themes.css`, `typography.css` and `motion.css`. 243 css/ts/tsx files hold about 5,212 token touches (scratch inventory `ds/inventory.md:3`, not retained). The hottest are `areas/shell.css` (540), `ui/ui.css` (348) and `collection/CollectionApp.tsx` (276) (inventory:4).
- Components read the existing names directly (`var(--canvas)`, `bg-surface-2` via `--color-canvas: var(--canvas)`, `tw-theme.css:5`). If a semantic name were renamed, every consumer of it would have to change. `scripts/tw-unknown-classes.mjs` would also fail every orphaned utility (inventory:754).
- Several checks pin current names or values. `F1.sh:7` pins the tokens.css declaration count at 163. `F1.sh:12` pins the tw-theme key count at 115. `built-css.sh:9` requires `--canvas:#0a0a0a` in the built CSS. `U1.sh:10-11` pins the spinner and colour-mix strings. `R3.sh:13` needs `vip-page-bg`. `R6.sh:15-18` needs `--brand-accent`, `--brand-accent-2`, `--canvas` and `--text-hi` in the lottery components. `census.sh:7` pins the CSS file list. `F1.sh:16` pins the globals `@import` list. `F5.sh:7` counts two font-loader `subsets` lines, and `S3.sh:7` requires the QuickActionRail `#fff|#171a21` literals. All of these checks, and `boxes.json`, are generated by `.unlazy/yaobet-rebuild/genplan.py` (lines 450, 455, 527-528, 565, 747, 761, 764, 922-928, 932, 989-997).
- `scripts/token-lint.mjs` locks the GROUP-A names (`:29-48`) and bans RAW-RAMP reads in components (`:52-55`). It pins `--focus-ring/--win/--loss/--error` as constants that never read `--brand-*` or the raw ramp (`:58`). It treats only `tokens.css`, `themes.css` and `brands.css` as definition files (`:61`).
- `<html>` ships with `data-theme="obsidian"` (`src/app/layout.tsx:79`), and `themes.css:19-21` is an empty obsidian block today. D-DS4 gives obsidian back its old values. If the attribute stays, those values would override `:root` on every page, and Wine-Gold would never show.
- `scripts/rebuild-rules.mjs:15-27` bans TSX classes for shadow, ring, gradient, `bg-(--x)` and `rounded-full`. Radius utilities such as `rounded-card` and `rounded-lg` are allowed: 47 tsx lines use them. They resolve through `tw-theme.css` to `--radius-*`. Re-pointing the token therefore changes radius without a TSX edit. Shadows can only come from CSS. The PM's statement holds: shadows and radius come through CSS tokens, not TSX utility classes. `rebuild-rules.mjs` stays unchanged.

## 2. Options

```yaml
tradeoffs:
  - option: A. Alias (selected)
    yagni_rung: 1
    summary: keep every existing custom-property name; re-point its value to a --wg-* primitive (semantic names) or to a semantic name (component names); add only the overlay names that have no current token
    pros: [no consumer churn for the swap itself, about 11 token files instead of about 243 consumer files (inventory:761), R3/R6/token-lint name pins keep holding, reversible per shard with one revert]
    cons: [legacy names such as --text-mid and --surface-2 stay next to new ones such as --fg-muted-raised, the MAPPING semantic names (--surface-canvas ...) are not introduced, so two naming styles live side by side]
    blast_radius: S0 = 13 files (7 token css, layout.tsx, token-lint, F1/built-css/I1/F5 checks); area adoption stays inside S1-S7; genplan.py mirrors happen in one closing shard (SG)
    risk: "low-medium: a value regresses silently because no consumer changes; mitigated by the parity and contrast checks"
    cost: one token shard, then shard-by-shard adoption of the component tokens
  - option: B. Rename to the MAPPING semantic names
    yagni_rung: 7
    pros: [one naming grammar (TOKENS.md §1), no legacy names]
    cons: [touches about 243 files and 5,212 sites in one go, breaks tw-unknown-classes for every renamed key, needs new pins in R3.sh:13 and R6.sh:15-18 and token-lint :29-55 (outside D-DS6), cannot be split into disjoint leases because every area reads the same names]
    risk: high
    cost: a rewrite across the repo with no visual gain
  - option: C. Dual alias (new names hold the values; old names read the new names)
    yagni_rung: 5
    pros: [makes a later rename mechanical]
    cons: [one extra declaration per re-pointed name, none with a consumer today (YAGNI), two hops per lookup, larger F1 count change]
    risk: low
    cost: medium; nothing uses the new names yet
  - option: D. Primitives in a new src/styles/brand.wine-gold.css (MAPPING.md:11)
    yagni_rung: 5
    pros: [primitives isolated in their own file]
    cons: [a new file breaks census.sh:7 and the F1.sh:16 import list, neither of which D-DS6 lets us change; token-lint treats it as a component file (token-lint.mjs:98)]
    risk: medium
    cost: two more check pins outside the owner's list
```

## 3. Decision

YAGNI rung: 1 (configuration). The swap is a change of token values plus the overlay names that have no current token (28 colour names on main: the 25 `semantic.color` and `component.color` entries of overlay.proposal.json minus `feedback.loss`, which re-points `--loss`, plus `--brand-accent-fg` and the three `--control-checked-*` names of §3.4). Rung 1 covers it, so rungs 2-7 are not needed.

1. **Alias strategy (option A).** Every name declared in tokens.css, brands.css and themes.css at 635a4dc stays declared; no name is deleted or renamed. A name that MAPPING marks "retired" (`--on-caution`, `--glow-gold`, `--progress-dot-glow`; MAPPING.md:88, :291-292) stays declared at the value MAPPING gives. Removing these dead names is a later clean-up, not this migration.
2. **Primitive tier `--wg-*`.** These are declared in one `:root` block at the top of `src/styles/tokens.css` (rejecting option D). Names follow MAPPING.md:16 (`--wg-color-gold-500`, `--wg-space-16`, ...). Each value is copied verbatim from `design-tokens.all.json` or `overlay.proposal.json`. The only new colour is the D-DS5 loss primitive, `primitive.color.red.300` → `--wg-color-red-300`. A primitive is declared only if a semantic token reads it, which leaves defect 7's orphans out. The `--wg-type-family-*` primitives may read the next/font loader variables (MAPPING.md:232).
3. **Tier rule (TOKENS.md:14).** The resolution path is: semantic names (the existing `--canvas`, `--surface*`, `--text-*`, `--win`, `--loss`, `--t-*`, `--space-*`, `--radius-*`, `--dur-*`, ...) → `var(--wg-*)`, then component names (existing ones such as `--header-bg`, `--balance-text`, `--progress-*`, plus the overlay names at MAPPING.md:132) → semantic names. Only the three definition files may read `--wg-*`. Brand and theme blocks override consumer-facing names, never `--wg-*`. A1 already allows only `--brand-*` in brand blocks (token-lint.mjs:108-113). `--win/--loss/--error/--focus-ring` read `--wg-*` primitives. This satisfies A3 (token-lint.mjs:114-123), because brand blocks cannot redeclare a `--wg-*` name.
4. **New names.** These are the overlay tokens with no current equivalent, named as in MAPPING.md:27, :123 and :132-134: `--fg-muted-raised`, `--accent-secondary-fg` (MAPPING.md:32), `--brand-accent-fg`, `--status-paused-fg|bg`, `--card-bg`, `--button-secondary-text`, `--control-checked-*`, `--input-*`, `--tab-text-*`, `--odds-up|down`, `--vip-bg`, `--vip-header-bg`, `--modal|toast|tooltip-border|meta`, `--feedback-bg-paused`, plus the overlay motion steps without a current token (MAPPING.md:306-307), and the overlay type-role tokens without a current token, named `--type-<role>-<prop>` per MAPPING.md:38 (PM ruling R5), the two semantic aliases `--line-default` and `--surface-wine-deep` (PM ruling R7), and the approved overlay rows `--touch-gap` and `--icon-sm|lg` (MAPPING.md:342-344, PM ruling R10). The MAPPING "repo semantic name" column (`--surface-canvas`, `--fg-primary`, ...) is not introduced (option C rejected; PM ruling R2). It records which DS role each existing name takes.
5. **Themes and brands (D-DS4, D-DS8).** `:root` becomes Wine-Gold. `layout.tsx:79` drops `data-theme="obsidian"`, so obsidian is opt-in again, as `themes.css:5` describes. Under D-DS4, "re-keyed to the new token names" maps to the existing names, because they are the ones components read (PM ruling R1). D-DS10 confirms the attribute removal; obsidian's values stay in themes.css, unused by default. The obsidian block in themes.css re-declares the old ladder on those names (MAPPING.md:158), together with the old win, loss, error and focus values (D-DS8). Emerald keeps its values (brands.css:36-52) and gains `--brand-accent-fg`. It keeps Montserrat, and the Montserrat loader stays (D-DS8) with `preload: false`, because only emerald uses it. Today emerald inherits `--brand-font-display: var(--font-head)` from tokens.css:362. Once `--font-head` moves to Playfair, emerald's display face would move with it. To prevent that, S0 adds `--brand-font-display` (the same Montserrat stack as brands.css:51) to the emerald block (brands.css:36-53), logged under D-DS8. Consequence: the h3-h6 rule in §3.6 moves emerald h3-h6 from Montserrat to the body face. The VIP palette (tokens.css:307-345) keeps its names and values. The `--vip-pal-*` re-key at MAPPING.md:160-177 is not done: no existing name collides with the new `--vip-bg|header-bg` names, and R3.sh:13 pins `vip-page-bg`.
6. **Fonts (D-DS3).** In `src/app/layout.tsx`, through `next/font/google`, Be Vietnam Pro, Playfair Display and Inter load with subsets `latin` and `vietnamese` and weights 400/500/600. Be Vietnam Pro drops 700 (`layout.tsx:42` at 635a4dc) and adds 500. Montserrat stays at 700/800 for emerald only (`layout.tsx:51-56`). Playfair is used only for the display, h1 and h2 roles. Everything else uses the body face (MAPPING.md:203, :230). Any place that asks for 700/800 from a face that ships no such weight moves to 600 (MAPPING.md:200, :209). No npm dependency is added; `hygiene.sh:11` stays exact.
7. **Components adopt shard by shard.** `ui.css` and the area CSS move to the component tokens in S1-S7. They also remove the hex and rgb literals listed in the inventory (inventory:18-99), or map them to tokens. SVG paint goes through `currentColor` plus a token-bound colour; per D-DS8 white maps to the ivory text token. Named exception (D-DS13): the `hsl()` illustration colours in `src/components/collection/CardArt.tsx` and `PackStage.tsx` stay as they are, while their `#fff` lines still move to tokens. `.ui-btn-danger` reads `--brand-cta-accent` (ui.css:213-220), which turns gold under D-DS7 (MAPPING.md:120). Its consumers `LogoutButton.tsx:40`, `Header.tsx:152` and the `text-brand-cta-accent` class at `MessageCenter.tsx:103` are reviewed by name in their shards and in GATES G19. Shadows and the gold sheen live in CSS only. tw-theme gets no `--shadow-*` keys, and MAPPING.md:31 and :58 do not bind TSX because `rebuild-rules.mjs:19` and `:22` ban those classes.
8. **Baseline (D-DS1, D-DS11, D-DS12).** Pixel parity with the original is retired; the screenshot gate A5 in the rebuild GATES is no longer run. The routes, auth-flow and hygiene gates stay as they are. The A5b box check stays at its 1 px tolerance, but S0 is expected to move boxes: line height goes 1.5 → 1.6 (MAPPING.md:196), weight 700 → 600 (:200), and numerals move to Inter (:202). The footer height reads `--lh-body` (shell.css:1506, :1557). S0 therefore logs every moved box (id, width, before, after). The designer and frontend-qc review that list, and a pin shard (SP) then re-pins `boxes.json` to the reviewed values. Every later shard runs the box check against the re-pinned file. Screenshots captured after the last merge become the new reference once the designer and frontend-qc have reviewed them. They live in `~/.cache/yaobet-ds/baseline`, outside git; only the sha256 manifest is committed (D-DS11).
9. **Check corrections (D-DS6, D-DS9, D-DS12, D-DS14).** A check changes only at an owner-approved pin, and every change is logged before → after. The pins are `F1.sh:7` and `:12` (D-DS6); `built-css.sh:9` (D-DS6); `U1.sh:10-11` (D-DS6); `built-css.sh:13`, `I1.sh:10` and `I1.sh:13` (D-DS9); `F5.sh:7` (2 → 4 subsets lines) and `S3.sh:7` (D-DS14); and the moved boxes in `boxes.json` (D-DS12). Each shard edits the pins that its own change breaks. Every other assertion stays untouched, and every static rebuild leaf check runs in every shard. token-lint.mjs is in the S0 lease, but the alias strategy removes no pinned name, so its expected diff is empty. genplan.py is touched only by the closing shard SG, which mirrors every pin at its generator line. It is never re-run, because a run would regenerate the rebuild ledgers. The committed allow list `.unlazy/yaobet-ds/checks/pins.txt` (GATES G4b; G4a re-runs every leaf check) names every pin and mirror line.

## 4. Consequences

- Positive: the palette, type, radius, elevation and motion swap lands in one reviewable shard (S0). Components then improve in disjoint leases. Reverting S0 and the shards in reverse order restores 635a4dc.
- Negative: two naming styles coexist until a later rename. A colour can regress without any consumer diff, so parity (MAPPING ↔ built CSS) and contrast are mechanised gates, not reviews.
- Neutral: the old reference shots stay where they are. The A5 justify rows (PR-48) no longer apply. `docs/rebuild/FIX-LIST.md` is unaffected, because no reproduced defect is fixed by the swap unless a shard says so.
- Follow-ups (not in scope): delete the retired names; rename to the MAPPING grammar (option C/B) if a later need appears; tokenise the raw durations in `areas/collection.css` (inventory:542-551); build a checkbox or switch component (none exists, inventory:737). Until then the D-DS8 checkbox tokens have no consumer; per R3 no checkbox component is built.
